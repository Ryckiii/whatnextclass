# 查查查课表

一个极简静态课表网站。支持自定义课表、课表码分享、手动选择星期、滚动浏览当天课程、自动定位当前时段、DDL 本地保存及到期清理。再也不用跑去看课表啦啦啦啦，再也不用担心错过ddl啦啦啦

## 使用说明

- 首次打开是课表编辑页：周一至周五，每天 11 个固定时间段（九节课与两节晚自习），课程名全部留空。填上课程名后点「使用这张课表」即可进入；也可以粘贴别人分享的课表码点「导入并使用」。
- 时间段固定不可改，只能填写每个时段的课程安排；同一格有多门课时用 ` / ` 分隔（例如 `物理C / 环科`），留空表示这段时间没有课。手机上点 Mon–Fri 切换要编辑的星期。
- 课表码是一段以 `W2.` 开头的纯 ASCII 文本（约两百字符），自带全部课程名。复制给同学、对方粘贴导入即可使用，不需要服务器或联网。
- 主界面左下角有「修改课表」与「导出课表码」：前者回到编辑页修改，后者显示并复制当前课表码。
- 保存过课表后，下次打开直接进入星期选择页；手动选择周一至周五，不会自动按实际日历星期选择。
- 课表页以 Mon / Tue / Wed / Thu / Fri 标注选定星期。
- 中央列表支持鼠标滚轮、触屏滑动、方向键及 Home / End；只显示课程名称。
- 当前课程以大号文字突出显示。休息期间显示当前休息状态，不把其它休息时段混入课程列表。
- 手动浏览后，可点击星期按钮旁的定位图标回到当前时段。
- 左上角加号添加 DDL，日期格式为 `yyyy.mm.dd`。列表最多显示三行，可继续滚动；悬停、键盘聚焦或触屏可使用删除按钮。剩余天数显示为 `· today`、`· 1 day`、`· N days`。
- 晚自习第一节 17:30–19:30，晚自习课间 19:30–19:45，晚自习第二节 19:45–21:00。
- 21:00 后显示完成提示并触发礼花；点「收好今天」才算完成，之后回到星期选择页，可以重新选择星期，当天不再提示、也不再触发礼花。只弹出过而没点确认，刷新页面不会重复弹，但仍算未完成。
- 本地午夜清空所选星期并清理过期 DDL。浏览器暂停后台标签页时，会在恢复可见或焦点时重新核对日期。

**无依赖、无构建步骤、无后端。入口文件为 `index.html`。**

## 课表码

- 格式：`W2.<Base64URL>`。先把 55 个格子按位宽打包，再把课程名字典一起做 deflate 压缩后编码，因此是一串纯 ASCII 字符、不含中文；重复课程越多，码越短（本班课表约 218 字符）。
- 纯前端编解码，不上传、不依赖服务器；导入时会校验格式，损坏或不完整的码会被拒绝，粘贴时带换行也能识别。
- 旧版以 `W1.` 开头的课表码仍可正常导入，导入后会自动改用新的压缩格式保存。
- 课表码只包含课程名文本，不含 DDL 或个人数据。
- 给别的班出码时请**写全课程名称**（一格多课用 ` / ` 分隔），不要使用 `S1` / `S2` / `S3` 这类代号，因为不同班的代号含义不同；本班课表码里的代号会由页面展开成完整课程名显示。

## 文件结构

```text
whatnextclass/                # 仓库根目录即网站根目录
├── index.html            # 应用入口：样式、脚本、SVG、礼花、课表编辑器均内嵌
├── README.md             # 使用与部署说明
├── .gitignore            # 排除常见系统和开发临时文件
└── .nojekyll             # GitHub Pages 按静态文件提供页面，跳过 Jekyll
```

站点入口必须是仓库根目录下的 `index.html`。早期的 `offline-timetable/` 打包目录已移除，不要再把它整个放进部署目录，否则访问路径会多一层 `/offline-timetable/`，仓库根网址会退回显示 README。

## 本地使用

直接用现代浏览器打开 `index.html`，不需要联网。

如需通过本地 HTTP 服务检查，且已安装 Python，可在此目录执行：

```bash
python -m http.server 8080
```

然后访问 `http://localhost:8080`。这只是可选的本地检查方式，部署不需要 Python。

## GitHub Pages 部署（推荐简单方式）

无需 Actions 工作流或 npm 构建。

1. 新建 GitHub 仓库，或打开你希望使用的现有仓库。
2. 将 `index.html`、`.nojekyll` 等文件提交到仓库根目录，确保根目录能直接看到 `index.html`（本仓库已经按此结构组织）。
3. 打开仓库 **Settings → Pages**。
4. 在 **Build and deployment → Source** 选择 **Deploy from a branch**。
5. 选择包含网站文件的分支（通常为 `main`），目录选择 **/(root)**，点击 **Save**。
6. 等待部署完成，使用 Pages 页面显示的网站地址访问。

普通项目仓库的网站地址通常为：

```text
https://<用户名>.github.io/<仓库名>/
```

此应用没有以 `/` 开头的资源路径，也没有路由重写要求，可以直接运行在仓库子路径下。

> GitHub Pages 是否可用于私有仓库取决于账户方案与组织设置。如果找不到 Pages 设置，请先检查仓库权限和 Pages 可用性。

### 已克隆仓库的命令行提交方式

先确认仓库根目录已有 `index.html` 与 `.nojekyll`；若已有同名文件，请先检查内容，避免覆盖原网站或项目配置。然后在仓库根目录执行：

```bash
git add index.html README.md .gitignore .nojekyll
git commit -m "Add timetable and local deadline app"
git push
```

Pages 只从所选分支（本仓库为 `main`）的 `/ (root)` 发布，因此改动需要合入该分支后才会生效；其它分支上的修改不会自动出现在网站上。

网页本身不需要 `node_modules`，仓库里也没有构建工具或第三方依赖。

## 其它静态托管平台

只要平台能够托管静态 HTML，即可使用此文件夹。常见配置为：

- 项目类型／框架：静态网站或 None / Other。
- 构建命令：不需要，留空。
- 发布目录：存放 `index.html` 的目录；若界面允许，可填 `.` 表示仓库根目录。
- 入口：`index.html`。
- 环境变量：无。
- 后端服务／数据库：无。

Git 仓库本身只存储代码；要通过网址使用，还需要开启 Pages 或连接静态托管服务。

## 数据与离线使用的重要说明

- 课表码、DDL、完成状态都只保存在当前浏览器的 `localStorage`，应用不会将它们上传到服务器或 Git 仓库。
- 本版保持旧版存储键名与数据格式：`y3c2.ddl.v1`（DDL 数组）与 `y3c2.finished.v1`（已确认完成的日期）不变，旧 DDL 不会丢失；另新增 `y3c2.table.v1`（课表码）与 `y3c2.shown.v1`（当天已弹出完成提示的日期）。
- 同一浏览器、同一站点来源下更新网站文件，通常会保留已有课表与 DDL。
- 从本地文件改为网站地址、切换域名／协议／端口、换浏览器或清除站点数据时，原有数据不会自动迁移；建议先把课表码导出留底。
- `localStorage` 按“协议 + 域名 + 端口”隔离，不按仓库路径隔离。在同一 `用户名.github.io` 域名下部署多个本应用副本，会共享同一组存储键及数据。
- 隐私模式或浏览器禁用存储时，数据可能无法长期保存；保存失败时页面会提示。
- 下载后的 `index.html` 可以完全离线打开。部署到网站后，首次访问需要联网；本包未添加 Service Worker，因此不保证断网时重新导航到网站地址能打开。已加载页面的功能与课表、DDL 操作不依赖网络。
- 课表码是分享课表的唯一方式；本版未增加云同步、账号或预置班级模板。压缩使用浏览器原生的 `CompressionStream`，较旧浏览器会退回未压缩的 `W1.` 格式，功能不受影响。
